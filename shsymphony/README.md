# 上海交响乐团 抢票工具

两套油猴(Tampermonkey)脚本，装一次、开票时零操作或一键操作：

| 目录 | 用途 | 适用页面 | 面板位置 |
| --- | --- | --- | --- |
| `preorder/` | **预售套票**（一次买多场，凑够场数拿优惠） | `.../#/zh-CN/pc/presale-schedule?tradeNo=...` | 右下角 |
| `single-concert/` | **单场选座**（单场按区域/连坐挑座抢） | `.../#/zh-CN/pc/seat?id=...&pk=...&sk=...` | 左下角 |

> 为什么不用控制台粘贴：开票前链接进不去；一旦进去抢票就开始了，那时再开控制台、输 `allow pasting`、贴代码就太迟。油猴脚本会**在页面一打开就自动就绪**。

---

## ⚡ 抢票当天速查（已装好的情况下）

1. 到点，进对应页面（预售选场页 / 选座页）。
2. 页面角落出现面板：
   - 预售：右下角「SHS 预售套票抢票」，状态显示 `✅ 选场页就绪，可抢票`。
   - 选座：左下角「SHS 单场选座抢座」，状态显示 `✅ 选座页就绪`。
3. 点 **一键抢票 / 一键抢座**，或按快捷键：
   - 预售：`Alt+Shift+P` 预演 · `Alt+Shift+R` 抢 · `Alt+Shift+X` 释放
   - 选座：`Alt+Shift+P` 预演 · `Alt+Shift+R` 抢 · `Alt+Shift+I` 库存
4. 抢到后，**手动点页面「提交订单」并付款**（脚本绝不替你付款；锁座给你留 15 分钟）。

> 想全自动零点击：把对应 `config.yaml` 里 `autoRun` 设为 `true`，重新 build 并在油猴「检查更新」。开票页一加载好就自动执行。

**每次抢票前务必先做一次「开票前 5 分钟自检」（见下）**，否则容易到点才发现用不了。

## 一次性安装（第一次用，或换电脑）

### 1. 装 Tampermonkey
Chrome 应用商店安装 Tampermonkey 扩展。

### 2. 开启「允许用户脚本」⚠️ 最容易踩的坑
新版 Chrome 默认禁止油猴运行脚本，装了也**静默不跑**。必须打开：
- 进 `chrome://extensions`
- **新版**：点 Tampermonkey「详情」→ 打开「**允许用户脚本 / Allow user scripts**」
- **稍旧版**：打开右上角「**开发者模式 / Developer mode**」

> 公司电脑若被策略锁死开发者模式，Chrome 里就跑不了；改用 **Firefox + Tampermonkey**（无此限制），安装地址一样。

### 3. 安装两个脚本
Chrome 已禁止直接用 `file://` 安装用户脚本，所以走本地小服务：

```bash
./build.sh all      # 先生成脚本
./build.sh serve    # 启动本地服务，保持这个终端开着
```

浏览器分别打开下面两个地址，Tampermonkey 会弹出安装页，点「安装」：
- `http://127.0.0.1:8770/preorder/preorder.user.js`
- `http://127.0.0.1:8770/single-concert/single-concert.user.js`

装完可以 `Ctrl+C` 停掉服务——**抢票时不需要它**，它只用于安装/更新。

> 备选（完全不用服务）：油猴面板「+ 新建脚本」，把生成的 `*.user.js` 内容整段粘贴进编辑器保存。油猴编辑器允许粘贴。

## 配置

改配置只改各自的 `config.yaml`，然后重新 build + 在油猴「检查更新」。

### 预售套票 `preorder/config.yaml`

```yaml
desiredSessions: 10      # 期望锁到的场次数（不够会自动从 backup 补）
preferConnected: false   # 买≥2张时是否强制连座（true 更可能抢不到）
autoRun: false           # true = 选场页一开就自动抢，全程零点击

sessions:                # 主选清单：数组顺序=抢票优先级（从上往下依次锁）
  - date: "2026-09-13"           # 匹配 playTime 前缀（可留空）
    title: "肖斯塔科维奇第十交响曲" # 网页节目标题的子串（可留空；与 date 同时满足）
    slots:                        # 每个 slot 是一条“降级链”，从左到右取第一个买得到的
      - ["80x1", "180x1", "380x1"]   # "价格x张数"

backup:                  # 备用清单：主选不够 desiredSessions 时按顺序补
  - date: "2026-09-25"
    title: "布兰诗歌"
    slots:
      - ["80x1", "180x1", "380x1"]
```

**降级链怎么理解**（你给的经典例子）：
```yaml
slots:
  - ["80x2", "180x1", "280x1"]   # 槽1
  - ["180x1", "380x1"]           # 槽2
```
- 最想要：`80×2 + 180×1`
- 80 没了：槽1 退到 180×1，槽2 仍 180×1 → 共 `180×2`
- 180 也不够：槽1 退到 280×1，槽2 退到 380×1 → `280×1 + 380×1`

**规则**：提交订单需 **≥5 场**；每场最多 **4 张**；订单有 **15 分钟**倒计时。
链中该场不存在的价位会自动跳过；**80 元档多数主线场已售罄**，所以每场都要带 180/380 等更高档做降级，否则凑不满。

### 单场选座 `single-concert/config.yaml`

```yaml
# scheduleId / mobile 可选；运行时 id/pk/sk 自动从选座页 URL 读取
dryRun: false           # true = 只预演不真正锁座
autoRun: false          # true = 选座页一开就自动抢
maxRetryPerRule: 40     # 被抢座后自动“刷新库存→重挑”的最多次数

rules:                  # 有序备选链：从上往下依次尝试，第一条成功即停
  - price: 80           # 票价（按数值匹配该场价位）
    qty: 2              # 张数
    areas: [J, C, D]    # 区域偏好，按顺序尝试
```
选座策略（已写死进引擎）：区域优先 → 连坐优先（同排连坐 > 上下排紧挨）→ 越靠中心越好；A/C/J 区不分左右，B/D/E/F/G/H/I 区优先右边(双号)。

## 构建命令 `./build.sh`

```bash
./build.sh preorder          # 只构建预售脚本
./build.sh single-concert    # 只构建选座脚本
./build.sh all               # 两个都构建
./build.sh serve [端口]      # 启动本地安装/更新服务（默认 8770）
./build.sh --help            # 帮助
# 可选联网校验配置里的场次/票价/区域是否存在（需 cookie）：
SHS_COOKIE="k=v; ..." ./build.sh preorder --live
```

改完 `config.yaml` 的更新流程：
```bash
./build.sh preorder    # 或 all，重新生成（版本号会自增）
./build.sh serve       # 再开一下服务
```
然后到油猴对该脚本点「**检查更新**」（脚本头的 `@updateURL` 已指向本地服务）。

## ✅ 开票前 5 分钟自检（强烈建议每次都做）

1. Chrome `chrome://extensions`：Tampermonkey 已启用，且「允许用户脚本/开发者模式」是**开**的。
2. 打开任意上交页面，看角落有没有面板；F12 Console 有没有 `[SHS] 已加载(预售)。` / `[SEAT] 已加载(单场选座)。`。
3. 点浏览器上的 Tampermonkey 图标，确认对应脚本**已启用**、图标有数字角标（表示在此页运行）。
4. 确认 `config.yaml` 是你要的（场次/价位/张数/autoRun），且已 build + 在油猴更新到最新版本。
5. 若用 `autoRun`，先在能进的页面确认面板状态正常，避免开票瞬间才发现没生效。

## 常见问题

- **控制台 `SHS is not defined`、没有面板、Console 无 `[SHS] 已加载`**
  → 油猴没在跑脚本。九成是没开「允许用户脚本 / 开发者模式」（见安装第 2 步），开启后**刷新页面**。
- **直接用 Chrome 打开 `*.user.js` 装不了 / 只下载**
  → Chrome 已禁 `file://` 安装。用 `./build.sh serve` 后开 `http://127.0.0.1:8770/...` 安装。
- **面板不出现**
  → 面板在本站任意页面都常驻；若确实没有，多半还是脚本没注入（同第 1 条）。到了对应路由(选场页/选座页)状态才会变「✅ 就绪」。
- **`http://127.0.0.1:8770/...` 打不开**
  → 本地服务没在跑，执行 `./build.sh serve`（换端口：`./build.sh serve 9000`，同时改 `SHS_SERVE_PORT` 重新 build 或直接改脚本头地址）。
- **提示「订单已超时(1123)」**
  → 预售订单 15 分钟到期。重新进选场页拿新的 `tradeNo` 再跑。
- **重复运行会不会超买？**
  → 不会。已锁的场次会被识别为「已锁(上次)」计入，不重复抢同一场。想重来可点「释放」(Alt+Shift+X)。
- **预售凑不满 5 场 / 备用没补上**
  → 多半是那些场只配了已售罄的价位（如只写 80）。看结果表「明细/未成」列（会显示 `80售罄`），给 slots 加更高价位降级链。

## 说明与边界

- 脚本调用的是页面自身的接口/组件，等价于你手动点击，登录态由浏览器 cookie 自动带上。
- **付款永远手动**：脚本只负责锁座/占座，不会替你付款。
- 本地服务仅用于安装/更新，抢票时无需运行；它可能被系统回收，需要时重开即可。
- 目录：`preorder/` 与 `single-concert/` 各自独立；`build.sh`、`package.json`、`node_modules/` 为共享；`old/`、`scripts/` 为历史资料，与抢票无关。
